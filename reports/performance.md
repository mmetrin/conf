# Технический отчёт

## Что изменено

Проект перенесён на React 19.3.0. Рабочий адрес файла сохранён. Компоненты отвечают за сцену, фиксированные элементы, программу, форму и повторяемые поля; данные программы вынесены отдельно. Высокочастотные изменения выполняются без React setState и без рендера React на каждом кадре. Сборка — esbuild, локальные JS/CSS/assets без CDN.

Сохранены: 0,5 секунды отдельного лоадера; совмещение линз; распад и сборка проектора; включение луча и появление текста; автоматическое появление аудитории; ширина программы 560 px; узкая зона увеличения пунктов; затемнение у проектора; 20 кадров по 120 мс, паузы по 1 секунде и обратный порядок. Тексты, неразрывные пробелы, размеры и адаптивные правила перенесены из исходника.

## Что удалено

- Скрытая старая приглашательная секция, прежний final-info, служебный scrub/play и скрытый footer.
- Неиспользуемые массивы, чтение пикселей текста, треки и функции старого распада текста.
- Скрытая световая рейка программы и 120 потенциальных записей CSS-переменных, которые больше не влияли на её текст.
- 242 правила/анимации для отсутствующих элементов, старые фотографии и четыре прежних кадра из сборки.
- Повторяющиеся inline base64: используемые изображения и шрифты вынесены в локальные файлы, одинаковые ресурсы не дублируются.

Старый HTML оставлен только в папке baseline для сравнения, не как вторая рабочая версия.

## Что оптимизировано

- Один обработчик scroll и один браузерный RAF-планировщик. Измерения scroll-секций выполняются до записей стилей.
- Размеры слоя символов света больше не читаются на каждом атмосферном кадре.
- Контуры проектора семплируются один раз; resize не повторяет поиск границ в изображении.
- Пол скрытой фотографии не перерисовывается. Для видимого пола очищается только область траекторий.
- Луч рисуется непосредственно в видимый Canvas, без дополнительного полноэкранного копирования. Две масштабированные текстуры кешируются, при этом живые наклоны, маски, интенсивность и частицы сохранены.
- Только первый кадр фотографии входит в ожидание перед открытием. Остальные 19 декодируются двумя последовательными очередями, а не одним пиковым пакетом.
- Bitmap-кеш соответствует размеру изображения и DPR. При увеличении окна разрешение повышается по одному кадру, без удвоения всего кеша. Исходные PNG не изменены.
- Фотографии программы загружаются лениво, их размеры зарезервированы.
- Обработчики, observers, таймеры и RAF очищаются при unmount. Скрытая вкладка останавливает циклы. Лоадер скрывается, но его геометрия остаётся доступной: устранена ошибка resize после его удаления.

Микротест: 1440×900, масштаб .8, 15 прогревочных и 80 измеряемых кадров; обе версии принудительно завершают рисование одинаковым чтением пикселей. Он включает стоимость чтения и не отражает GPU браузера. Разницу скорости следует считать ориентиром, а не обещанием FPS. Сравнение одного кадра луча на чёрном фоне: RMSE 0.126 по шкале 0–255, максимальная разница 2.20 — от повторной выборки кешированной текстуры.

HTML стал меньше за счёт выноса ресурсов; это **не означает** такое же уменьшение всех сетевых загрузок. React добавляет runtime. Экономия декодированной памяти зависит от ширины, DPR и наличия createImageBitmap; на Retina исходное разрешение сохраняется.

## Проверки

7 автоматических тестов проходят: жизненный цикл React при моделируемых 1600×940, 768×1024 и 375×812; открытие, скролл в обе стороны, изменение размеров, reduced motion, скрытие вкладки, unmount; ошибки и заполнение формы; последовательность 20 кадров; декодирование всех PNG; существование ресурсов. Production-сборка проходит.

Lighthouse, LCP, INP, CLS, FCP, TBT, Speed Index, DevTools Performance/Memory и ручная визуальная проверка Chrome/Safari **не измерены**. В текущей сессии доступ к локальной странице через браузерную автоматизацию был ограничен политикой URL; обход не использовался. DOM-тесты с моделируемой геометрией и нативный Canvas не заменяют эти проверки. Поэтому полное устранение лагов и визуальное совпадение во всех браузерах пока не подтверждены.

## Основные узкие места

Пиковая подготовка 20 больших кадров, лишние текстовые пиксельные массивы и повторные измерения/записи при скролле устранены или сокращены. Живой WebGL-свет, несколько полупрозрачных масок и blur карточки остаются наиболее вероятной GPU-нагрузкой; без браузерного профиля её доля не доказана.

## Что ещё можно улучшить

- Снять настоящие before/after трассы в Chrome и Safari на целевых устройствах, проверить GPU, долгие задачи и Web Vitals.
- Решать вопрос изменения blur, детализации shader или частоты эффектов только по профилю: сейчас эффекты сохранены.
- Не добавлялся искусственный code splitting для небольшого shader-модуля; единый локальный bundle сохраняет открытие через file://.
- Остальные каскадные переопределения CSS сохранены там, где без реального браузерного сравнения нельзя доказать равенство адаптивного результата.
- Подключение реального адреса регистрации и ссылки на политику требует соответствующих данных. Форма не имитирует успешную отправку.
